## 动机

当前设置页采用紧凑工具顶栏与简单列表布局，与产品主界面（首页）在侧栏、顶栏搜索与会员入口、底栏品牌文案等视觉与信息结构上不一致，也难以在多页面间复用同一套壳层。需要以设计稿为基准，将设置页升级为与主应用一致的仪表盘式布局，并通过可复用壳层组件降低后续页面扩展成本。

## 变更范围

- 抽象并落地应用级布局壳层：左侧主导航、居中搜索与右侧会员或窗口控制、底部页脚文案，供首页、设置及其他主视图按需组合或复用。
- 按设计稿重构设置页主内容区：分组卡片（常规、输出、缓存、更新、隐私、关于等），行内控件形态（开关、下拉、分段主题、路径选择与危险操作按钮等）。
- 在保持现有 `settings.store` 与已持久化项可用的前提下，对新增设置项采用配置驱动或分区组件拆分；若设计项暂无后端或 Tauri 能力，则提供 UI 占位与 i18n 文案，并在实现阶段明确与 store 的映射或延后项。
- 统一路由进入设置页时的布局体验，避免设置页仍使用仅面向工具页的 `ToolPageTopBar` 作为唯一顶栏方案。

## 能力划分

### 新增能力

- `app-shell-layout`：应用壳层布局能力，涵盖侧栏导航结构、顶栏搜索与快捷提示、会员与设置入口、窗口控制区、底栏品牌区，以及主内容插槽约定与响应式或最小宽度约束。
- `settings-dashboard`：设置仪表盘能力，涵盖设置分组卡片、设置行（标题、说明、控件槽位）、主题分段控件、路径行（变更、打开）、关于区块与外链区等行为与展示要求。

### 变更的既有能力

- 仓库中 `openspec/specs/` 下暂无已归档主规格，本变更不声明对既有主规格的增量修改；若后续存在 `home-dashboard` 等主规格合并，再通过同步任务对齐。

## 影响面

- 前端：`SettingsPage.vue`、路由布局、`HomePage.vue` 中与侧栏或顶栏重复的实现需评估抽取；`src/components/common` 或 `src/pages` 下新增壳层与设置子组件；`src/i18n` 文案键扩展。
- 状态：`stores/settings.store` 可能随新开关与路径类设置扩展字段与持久化键名。
- Tauri 或文件系统：开机自启、托盘、默认输出目录、缓存目录与清理等若在设计中呈现，需评估现有命令与权限并在任务中标注依赖。
