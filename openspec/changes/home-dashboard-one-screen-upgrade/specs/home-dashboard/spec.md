## ADDED Requirements

### Requirement: 首页仪表盘区域划分

系统在首页必须将可见内容划分为：顶栏、主内容列、侧栏列、页脚；主内容列必须包含问候与主推区、主推工具卡片区、最近使用区、价值卖点横条；侧栏列必须包含三张独立信息卡：本地安全说明、会员权益、更新日志。

#### Scenario: 用户打开首页

- **WHEN** 用户导航至首页路由并渲染完成
- **THEN** 用户可见上述各区域且侧栏三张卡片标题与正文区域可区分

### Requirement: 推荐视口下一屏无页面级滚动

系统在 WebView 布局视口宽度不小于 1200px 且高度不小于 720px 时，首页根容器不得出现纵向页面级滚动条（`overflow-y: visible` 或等效，不得因本页布局导致整页 `scrollHeight` 大于 `clientHeight`）。

#### Scenario: 默认窗口尺寸下浏览首页

- **WHEN** 视口宽高分别至少为 1200px 与 720px 且用户未对首页根容器施加额外缩放
- **THEN** 页面级不出现纵向滚动条

#### Scenario: 纵向空间略紧但仍不低于阈值

- **WHEN** 视口高度恰为 720px 且宽度不低于 1200px
- **THEN** 主内容区通过 `min-height:0` 与 flex 分配避免将整页撑出视口，仍满足无页面级纵向滚动

### Requirement: 小于推荐视口时的降级行为

当视口宽度或高度低于上述阈值时，系统必须采用文档化的一种或多种降级策略：例如主列与侧栏改为纵向栈式排列，或允许主列/侧栏内部出现独立滚动区域；在此情形下不强制「无页面级滚动」，但必须保持内容可读且可聚焦交互，不出现横向裁切导致不可达控件。

#### Scenario: 窄宽度窗口

- **WHEN** 视口宽度小于 1200px
- **THEN** 布局切换为已定义的断点样式且不出现不可访问的交互控件

### Requirement: 主推工具卡与统一数据源

主推工具卡片区必须从与首页工具跳转及顶栏搜索一致的配置或 composable 导出数据中渲染卡片；每张可跳转卡片必须触发与当前产品一致的路由行为；必须提供「更多/即将推出」类占位卡且不指向未完成路由，或指向占位说明。

#### Scenario: 用户点击已上线工具卡

- **WHEN** 用户点击某一已配置路由的工具卡
- **THEN** 应用导航至对应工具页面

#### Scenario: 用户点击占位卡

- **WHEN** 用户点击「更多」或「即将推出」占位卡
- **THEN** 应用不导航至不存在路由，或展示明确的占位反馈（与 `design.md` 中 Open Questions 落地结果一致）

### Requirement: 侧栏卡片内容与会员占位

本地安全说明卡必须列出与「本地处理、隐私、离线」等价值主张一致的要点（文案经 i18n）；会员权益卡必须展示权益列表与主行动按钮，首版支付未接时按钮为占位且行为符合设计文档；更新日志卡必须展示至少两条版本记录（可为静态配置），含版本号与简短说明。

#### Scenario: 用户阅读侧栏

- **WHEN** 用户注视侧栏三张卡片
- **THEN** 可识别安全要点、会员权益摘要与最近版本信息

#### Scenario: 用户点击会员占位按钮

- **WHEN** 用户点击会员主行动按钮且支付未接入
- **THEN** 系统给出与设计文档一致的占位反馈且不抛出未处理异常

### Requirement: 顶栏与页脚信息

顶栏必须展示应用名称与副标题（经 i18n）、搜索入口及占位提示、设置入口；在桌面端必须与窗口控件区域不重叠（沿用现有布局约定）。页脚必须展示当前版本标识与 slogan 或版权相关文案（经 i18n），与产品版本源一致或明确为展示用静态串。

#### Scenario: 用户查看顶栏与页脚

- **WHEN** 首页渲染完成
- **THEN** 顶栏搜索占位与页脚版本及 slogan 可见且文案键可切换语言

### Requirement: 组件边界与页面编排职责

`HomePage.vue` 或等价路由页面组件必须仅承担布局编排与子事件聚合（如跳转、搜索选中）；问候区、主推卡片区、价值卖点横条、侧栏各卡必须各自为独立单文件组件或通过明确子目录组织；视图模型拼装必须优先位于 composable 与 `config`/`types`，避免在页面组件内硬编码长列表数据。

#### Scenario: 维护者定位代码

- **WHEN** 维护者需要仅修改「价值卖点横条」文案或图标
- **THEN** 其修改范围可限制在该横条组件与 i18n 或配置文件中，无需改动无关组件业务逻辑

### Requirement: 键盘与可访问性基线

主推工具卡与占位卡若使用 `button` 或带 `role` 的可聚焦元素，则必须支持键盘聚焦可见样式；搜索快捷键提示若展示「Ctrl K」类文案，则必须与实际打开搜索行为一致或在规格备注中说明平台差异（例如 macOS 使用 Command）。

#### Scenario: 键盘用户聚焦工具卡

- **WHEN** 用户使用 Tab 键在主推卡片区移动焦点
- **THEN** 当前聚焦卡片具备可见焦点环或等效对比度样式
